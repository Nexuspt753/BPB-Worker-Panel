    اسم کانفیگ‌ها

    بخش Config Names اسم کانفیگ‌هایی را که BPB می‌سازد کنترل می‌کند. قالب اسم به‌صورت پیش‌فرض خالی است؛ بنابراین تا وقتی چیزی تنظیم نکنید، اسم‌های قدیمی بر اساس نوع آدرس و پورت حفظ می‌شوند.

    مثال:

    {MARKER}{FLAG}{COUNTRY} - {IP} [[ - {IPNAME}]]

    هنگام تایپ، autocomplete فعال است. با وارد کردن { فهرست متغیرها باز می‌شود، با تایپ بیشتر فیلتر می‌شود و با کلیدهای بالا/پایین و Enter یا Tab می‌توانید یک مورد را وارد کنید.

    ساختار قالب

    متغیرها با یک جفت آکولاد نوشته می‌شوند، مثل {IP} یا {COUNTRY_CODE}. نام متغیرها به حروف بزرگ و کوچک حساس نیست. برای هر متغیر می‌توانید مقدار جایگزین محلی بنویسید، مثل {CITY|Unknown}. برای بخش‌های اختیاری از جفت براکت غیرتودرتوی زیر استفاده کنید:

    {IP}[[ - {IPNAME}]][[ ({LATENCY}ms)]]

    وقتی همه متغیرهای داخل یک بخش اختیاری خالی یا در دسترس نباشند، کل آن بخش حذف می‌شود؛ در نتیجه جداکننده‌های اضافی باقی نمی‌مانند. بخش اختیاری باید حداقل یک متغیر داشته باشد؛ [[text]] خالی از متغیر رد می‌شود چون شرطی برای حذف یا نمایش آن ندارد.

    قالب‌های خراب قبل از ذخیره رد می‌شوند. نمونه‌ها:

    • {{IP}COUNTRY} — متغیر تودرتو
    • {IP یا IP} — آکولاد ناقص
    • {} — متغیر خالی
    • [[{IP} — براکت اختیاری ناقص
    • [[[[{IP}]]]] — بخش اختیاری تودرتو
    • {NOT_A_TOKEN} — متغیر ناشناخته
    • {CITY|} — مقدار جایگزین خالی
    • [[literal only]] — بخش اختیاری بدون متغیر

    پنل محدوده، خط/ستون و دلیل خطا را نشان می‌دهد. متغیرهای معتبر کنار هم، مثل {IP}{PORT}، پشتیبانی می‌شوند.

    Preset و پیش‌نمایش زنده

    منوی preset چند قالب آماده دارد:

    • Compact: {FLAG} {IP}:{PORT}
    • Detailed: {MARKER}{FLAG}{COUNTRY} - {IP} [[ - {IPNAME} ]]
    • Latency ranking: [[{LATENCY}ms | ]]{FLAG} {IP}
    • Protocol-aware: {PROTO} {MARKER}{IP}:{PORT}

    در Live examples نمونه‌هایی از VLESS، Trojan، Clean IP، Fragment/Chain و Warp نمایش داده می‌شود و تنظیمات حریم خصوصی geo، latency و گروه‌های آدرس روی آن‌ها اعمال می‌شود. بخش Collision preview اسم‌های خام تکراری و اسم نهایی پس از اجرای همان منطق یکتاسازی backend را نشان می‌دهد؛ این‌ها نمونه هستند و الزاماً آدرس‌های واقعی نصب شما نیستند. اگر درخواست preview در دسترس نباشد، پنل هشدار اتصال را جدا از خطای syntax قالب نشان می‌دهد.

    متغیرهای قابل استفاده

    متغیر معنی
    {MARKER} علامت نوع کانفیگ: F برای Fragment، D برای دامنه سفارشی و C برای CDN سفارشی؛ در حالت عادی خالی است.
    {FLAG} / {F} پرچم کشور؛ {F} نام قدیمی همین متغیر است.
    {COUNTRY} / {C} نام کشور؛ {C} نام قدیمی است.
    {COUNTRY_CODE} کد دوحرفی ISO کشور.
    {CITY} شهر.
    {REGION} منطقه یا استان.
    {ISP} ارائه‌دهنده اینترنت.
    {ASN} شماره سیستم خودمختار.
    {TYPE} نوع اتصال: Hosting، Mobile یا Residential.
    {GEO_AGE} عمر داده جغرافیایی cache شده، مثل 2h یا 1d.
    {GEO_SOURCE} منبع داده جغرافیایی: egress، dial، cached یا unavailable.
    {LATENCY} تأخیر اندازه‌گیری‌شده از Worker به endpoint، در صورت فعال بودن تست خودکار.
    {LATENCY_AGE} عمر داده تأخیر cache شده.
    {IP} / {D} آدرسی که کانفیگ به آن وصل می‌شود؛ {D} نام قدیمی است.
    {IPNAME} نام بعد از # در ورودی Clean IPs.
    {GROUP} برچسب تعریف‌شده در بخش Address groups.
    {EGRESS_IP} آدرس خروجی شناخته‌شده؛ اگر قابل تشخیص نباشد خالی می‌ماند. {IP} همیشه آدرس dial است.
    {INDEX} شماره کانفیگ.
    {PORT} پورت کانفیگ.
    {PROTO} پروتکل، مثل VLESS، Trojan یا Warp.
    {CHAIN} برای نسخه Chain مقدار 🔗 و در غیر این صورت خالی.
    {B} نام برند BPB.
    {SECURITY} امنیت اتصال، مثل TLS یا None.
    {TRANSPORT} نوع انتقال، مثل WS یا WireGuard.
    {SNI} / {HOST} مقدار SNI و Host اتصال.
    {FAMILY} خانواده آدرس: IPv4، IPv6 یا Domain.
    {DOMAIN} دامنه‌ای که کانفیگ با آن ساخته شده است.
    {CORE} هسته سازنده، مثل xray، sing-box، clash یا wireguard.
    {KIND} نوع کانفیگ، مثل Normal، Fragment، Chain، Best Ping، Warp یا Imported.

    متغیری که مقدار ندارد به شکل -- نمایش داده می‌شود. {MARKER}، {CHAIN} و {GROUP} وقتی کاربردی ندارند خالی می‌مانند و برای قرار دادن داخل بخش‌های اختیاری مناسب هستند.

    محل اعمال اسم‌ها

    نوع خروجی پشتیبانی
    Normal VLESS/Trojan اسم یا tag در Xray، sing-box و Clash
    Fragment و Chain اسم یا tag در خروجی‌های پشتیبانی‌شده Xray، sing-box و Clash
    Best Ping و Smart Fragment remark کانفیگ‌های Xray
    اشتراک Raw اسم VLESS/Trojan و Chain و URIهای واردشده پشتیبانی‌شده
    Warp و Warp Pro Xray، sing-box و Clash
    WireGuard و Amnezia نام فایل‌های داخل ZIP، با کاراکترهای امن برای فایل‌سیستم
    کانفیگ‌های خارجی URIهای VLESS، Trojan، VMess، Shadowsocks، SOCKS و HTTP؛ فرمت‌های ناشناخته بدون تغییر می‌مانند

    قالب خالی رفتار قبلی را حفظ می‌کند. بعد از تغییر قالب، اشتراک‌ها را دوباره دریافت یا به‌روزرسانی کنید.

    یکتاسازی و جلوگیری از Collision

    هسته‌های مختلف از اسم به‌عنوان شناسه استفاده می‌کنند: Clash از proxy name، sing-box از outbound tag، Xray از remark و WireGuard از نام فایل استفاده می‌کند. بنابراین اسم‌های تولیدشده باید یکتا باشند.

    یک قالب معتبر دقیقاً همان خروجی تعریف‌شده را تولید می‌کند؛ اطلاعاتی که در قالب نیامده‌اند، مثل آدرس، پروتکل یا پورت، خودکار به انتهای نام اضافه نمی‌شوند. برای نمونه، {COUNTRY} فقط Germany تولید می‌کند، نه Germany VLESS 443 ~a1b2c3d4.

    هسته‌های کلاینت همچنان به شناسه‌های یکتا نیاز دارند. اگر خروجی تولیدشده واقعاً با نام دیگری یا با یک شناسه رزروشده مانند selector، DNS، inbound یا URL-test تداخل داشته باشد، فقط همان خروجی متداخل یک پسوند ثابت بر اساس هویت می‌گیرد؛ برای نمونه ~a1b2c3d4-2. این fingerprint از هویت canonical کانفیگ ساخته می‌شود، نه ترتیب لیست. host، دامنه، port، براکت IPv6 و نقطه پایانی دامنه قبل از hash استاندارد می‌شوند؛ بنابراین جابه‌جایی ترتیب آدرس‌ها نام غیرمتداخل را تغییر نمی‌دهد.

    حداکثر طول ابتدا روی خروجی قالب اعمال می‌شود. اگر به‌دلیل یک تداخل واقعی نیاز به پسوند باشد، پیاده‌سازی حد تعیین‌شده را حفظ می‌کند و تا حد ممکن یک نام یکتای قطعی می‌سازد.

    گروه‌بندی آدرس‌ها

    Address groups اجازه می‌دهد یک برچسب را به چند آدرس بدهید. این قابلیت با IPNAME که برای هر آدرس در Clean IPs ثبت می‌شود فرق دارد.

    می‌توانید از header و خطوط بعدی استفاده کنید:

    Cloudflare Fast:
1.1.1.1
1.0.0.1
[2606:4700::1111]

Backup: 8.8.8.8, example.com

    بعد در قالب از {GROUP} استفاده کنید:

    {GROUP} - {IP}

    براکت IPv6 هنگام تطبیق نادیده گرفته می‌شود و اگر کنار host یک port اختیاری نوشته شود، port در تطبیق نادیده گرفته می‌شود. IPv6 خام و شکل [IPv6]:port هر دو قابل استفاده هستند. گروه‌ها فقط با hostهای منفرد تطبیق داده می‌شوند؛ بازه‌های CIDR برای IPv4 و IPv6 رد می‌شوند چون تطبیق subnet پشتیبانی نمی‌شود. host نامعتبر، گروه خالی و ورودی خراب در اعتبارسنجی backend گزارش می‌شود. اگر یک آدرس چند بار تعریف شود، تعریف آخر برچسب آن را جایگزین می‌کند.

    اطلاعات جغرافیایی و خروجی واقعی

    {IP} و {D} آدرسی را نشان می‌دهند که کلاینت به آن وصل می‌شود. متغیرهای جغرافیایی ترجیحاً آدرسی را توصیف می‌کنند که ترافیک از آن خارج می‌شود، نه الزاماً آدرس Cloudflare مقصد. در حالت Proxy IP، اولین Proxy IP تنظیم‌شده به‌عنوان خروجی احتمالی استفاده می‌شود. در حالت‌های دیگر Worker آدرس خروجی عمومی خود را اندازه‌گیری و cache می‌کند. اگر خروجی مشخص نشود، geo ممکن است از اطلاعات آدرس مقصد استفاده کند و {GEO_SOURCE} مقدار dial را نشان می‌دهد؛ {EGRESS_IP} در این حالت خالی می‌ماند.

    قالبی که فقط متغیرهایی مثل {IP}، {PORT}، {INDEX} یا {PROTO} دارد، درخواست geo provider نمی‌فرستد. جستجوی geo timeout پنج‌ثانیه‌ای، memo داخل isolate، cache در KV، داده قدیمی در صورت وجود و سقف درخواست دارد تا خرابی یا rate limit سرویس بیرونی اشتراک را خراب نکند.

    ثابت نگه داشتن اسم‌ها

    گزینه Freeze geo-derived names را فعال کنید تا تغییر کشور، شهر، ISP یا آدرس خروجی شناخته‌شده باعث تغییر اسم کانفیگ‌های قبلی نشود. این گزینه برای متغیرهای geo و {EGRESS_IP} اعمال می‌شود. اسم‌های ثابت بر اساس هویت پایدار کانفیگ در KV ذخیره می‌شوند و در درخواست‌های بعدی استفاده می‌شوند. برای ساخت snapshot جدید نیز فقط از geo/egress cache استفاده می‌شود.

    با Regenerate frozen names snapshotها را پاک کنید تا در دریافت بعدی اشتراک، اسم‌ها دوباره ساخته شوند. چون این کار ممکن است اسم‌ها را در کلاینت تغییر دهد، دکمه عمداً جدا و صریح است.

    رتبه‌بندی بر اساس Latency

    برای تولید {LATENCY} و {LATENCY_AGE} گزینه Auto-test endpoint latency را فعال کنید. بازه بین ۱۰ تا ۱۴۴۰ دقیقه است. تست از شبکه Worker انجام می‌شود، نه دستگاه کاربر، و برای رتبه‌بندی نسبی مناسب است.

    تست‌ها با concurrency محدود، حذف endpointهای تکراری بر اساس آدرس و port، در نظر گرفتن upstream targetهای تنظیم‌شده و timeout اجرا می‌شوند و همان port مورد استفاده کانفیگ را تست می‌کنند؛ فقط پاسخ سالم Cloudflare ذخیره می‌شود. sweep بعد از پاسخ اشتراک انجام می‌شود و خطای probe یا KV نباید دریافت اشتراک را خراب کند. وقتی تست خودکار خاموش است، مقدار قدیمی latency به‌عنوان {LATENCY} فعلی نمایش داده نمی‌شود.

    تست دستی صفحه Proxy IP جداست و این متغیر را پر نمی‌کند.

    قالب‌بندی و حریم خصوصی

    • Readable فاصله‌های تکراری را جمع می‌کند و Unicode را حفظ می‌کند.
    • Compact فاصله‌های غیرضروری اطراف | و · و separatorها را کم می‌کند.
    • ASCII-safe برای کلاینت‌های سخت‌گیر، accent و نمادهای غیر ASCII را حذف می‌کند.
    • Maximum name length مقدار 0 را برای بدون محدودیت می‌پذیرد و عددی بین ۸ تا ۲۰۰ را قبول می‌کند. طول خود قالب نیز حداکثر ۲۰۰ کاراکتر است. مقدار کمتر از ۸ نمی‌تواند fingerprint یکتا را حفظ کند و رد می‌شود؛ کوتاه‌سازی بر اساس grapheme انجام می‌شود تا emoji یا حروف ترکیبی خراب نشوند.

    حالت‌های حریم خصوصی geo:

    • Automatic lookup with cache در صورت استفاده از متغیر geo می‌تواند از provider داده بگیرد و cache کند.
    • Cached data only هیچ درخواست تازه‌ای برای geo نمی‌فرستد.
    • Disable geo lookups providerهای geo را صدا نمی‌زند؛ متغیرهای geo بدون مقدار می‌مانند و بهتر است داخل بخش اختیاری باشند.

    با {GEO_AGE} و {LATENCY_AGE} می‌توانید عمر داده را در اسم نشان دهید.

    مهاجرت و fallback

    نسخه nameTemplateVersion همراه تنظیمات ذخیره می‌شود. هنگام بارگذاری تنظیمات قدیمی، مهاجرت فعلی Unicode و spelling متغیرها را استاندارد می‌کند و متن اطراف آن‌ها را تغییر نمی‌دهد. مقدار جایگزین متغیر با قالب {TOKEN|value} نوشته می‌شود. import تنظیمات هم با همین parser اعتبارسنجی می‌شود.

    اگر قالب خالی، خراب یا برای یک کانفیگ فاقد مقدار معنادار باشد، BPB به اسم کلاسیک همان نوع کانفیگ برمی‌گردد و اسم خالی تولید نمی‌کند. اگر چند کانفیگ منطقی همین fallback را داشته باشند، برای یکتا ماندن شناسه کلاینت ممکن است یک پسوند ثابت بر اساس هویت اضافه شود. فرمت‌های ناشناخته کانفیگ خارجی نیز هیچ‌وقت بازنویسی نمی‌شوند.
