# :material-tag-multiple:{ .md .middle } اسم کانفیگ‌ها

به‌صورت پیش‌فرض اسم هر کانفیگی که ساخته میشه بر اساس نوع آدرس و پورتش ساخته میشه. اگه اسم‌های توصیفی‌تری می‌خواید، از این بخش می‌تونید یه **قالب اسم** دلخواه تعریف کنید که برای هر کانفیگ به‌صورت خودکار از روی اطلاعات جغرافیایی (کشور، شهر، استان، ارائه‌دهنده سرویس و نوع اتصال) و اسم‌های دلخواهی که خودتون تعیین می‌کنید پر بشه.

قالب به‌صورت پیش‌فرض خالیه؛ تا وقتی قالب ننویسید، اسم کانفیگ‌ها با آدرس و پورت قبلی می‌مونه. برای مثال:

```
{MARKER}{FLAG}{COUNTRY}{CITY} - {IP} - {IPNAME}
```

می‌تونید قالب رو به هر ترکیبی از متغیرهای زیر تغییر بدید.

کادر قالب هم فهرست پیشنهادی دارد: با زدن `{` لیست باز می‌شود، با ادامهی تایپ فیلتر می‌شود و با کلیدهای بالا/پایین و Enter یا Tab می‌توانید یک مورد را درج کنید. فهرست فقط وقتی نمایش داده می‌شود که مکان‌نما داخل یک `{...}` باز است.

برای بخش‌های اختیاری از `[[...]]` استفاده کنید؛ مثلاً قالب `'{IP}[[ - {IPNAME}]]'` وقتی `{IPNAME}` موجود نباشد جداکننده و نام سفارشی را هم حذف می‌کند. بخش‌های اختیاری قابل تودرتو نیستند و براکت‌ها یا آکولادهای ناقص قبل از ذخیره رد می‌شوند.

از منوی preset می‌توانید یکی از قالب‌های Compact، Detailed، Latency ranking یا Protocol-aware را انتخاب کنید. پیش‌نمایش زنده چند نمونه از کانفیگ‌های معمولی، فرگمنت، chain و Warp را نشان می‌دهد و بخش collision preview نام‌های تکراری را قبل از اضافه شدن پسوندهای یکتا مشخص می‌کند.

!!! info "راهنمایی"
    هر متغیری که مقدارش مشخص نباشه به صورت `--` نمایش داده می‌شه، بنابراین شکل قالب همیشه ثابت می‌مونه حتی وقتی اطلاعات جغرافیایی در دسترس نباشه. `{MARKER}` و `{CHAIN}` استثنا هستن: وقتی اعمال نشن خالی می‌مونن.

## متغیرهای قابل استفاده

- `{MARKER}` — پیشوند نوع کانفیگ (شامل `F` برای فرگمنت، `D` برای دامنه شخصی و `C` برای CDN سفارشی)؛ وقتی هیچ‌کدوم اعمال نشده باشه خالیه.
- `{FLAG}` — ایموجی پرچم کشور.
- `{COUNTRY}` — اسم کشور.
- `{COUNTRY_CODE}` — کد دوحرفی ISO کشور.
- `{CITY}` — اسم شهر.
- `{REGION}` — اسم منطقه یا استان.
- `{ISP}` — ارائه‌دهنده خدمات اینترنت.
- `{ASN}` — شماره AS.
- `{TYPE}` — نوع اتصال: `Hosting` یا `Mobile` یا `Residential`.
- `{GEO_AGE}` — عمر داده جغرافیایی ذخیره‌شده، مثل `2h` یا `1d`.
- `{LATENCY}` — تأخیر به میلی‌ثانیه؛ با تست خودکار اختیاری زیر تازه می‌مونه، و وقتی مقدار اندازه‌گیری‌شده‌ای وجود نداشته باشه `--` نشون می‌ده.
- `{LATENCY_AGE}` — عمر داده تأخیر ذخیره‌شده.
- `{IP}` — آدرس کانفیگ.
- `{EGRESS_IP}` — آدرس IP که ترافیک شما واقعاً از اون خارج می‌شه (در ادامه توضیح داده شده).
- `{IPNAME}` — اسم دلخواهی که برای آدرس تعیین کردید (در ادامه توضیح داده می‌شه).
- `{PROTO}` — پروتکل کانفیگ.
- `{CHAIN}` — برای نسخه chain proxy یه کانفیگ 🔗 می‌ذاره؛ در غیر این صورت خالیه.
- `{INDEX}` — شماره ایندکس کانفیگ.
- `{PORT}` — شماره پورت کانفیگ.
- `{B}` — اسم برند پنل.
- `{F}` — همون پرچم کشوره (نسخه قدیمی).
- `{D}` — آدرس یا دامنه (نسخه قدیمی).
- `{C}` — اسم کشور (نسخه قدیمی).
- `{SECURITY}` — امنیت اتصال، مثل `TLS` یا `None`.
- `{TRANSPORT}` — نوع انتقال، مثل `WS` یا `WireGuard`.
- `{SNI}` / `{HOST}` — مقدار SNI و host اتصال.
- `{FAMILY}` — خانواده آدرس: `IPv4`، `IPv6` یا `Domain`.
- `{DOMAIN}` — دامنه‌ای که کانفیگ با آن ساخته شده.
- `{CORE}` — هسته سازنده، مثل `xray`، `sing-box`، `clash` یا `wireguard`.
- `{KIND}` — نوع کانفیگ، مثل `Normal`، `Fragment`، `Chain`، `Warp` یا `Best Ping`.

اسم متغیرها به بزرگی و کوچکی حروف حساس نیست، یعنی `{flag}` و `{FLAG}` یکی هستن. نسخه قالب همراه تنظیمات ذخیره می‌شه تا نام‌های قدیمی هنگام مهاجرت بدون تغییر ناخواسته حفظ بشن.

!!! tip "نکته"
    ایموجی `{FLAG}` از کد دو حرفی کشوری که از جستجوی جغرافیایی برمی‌گرده ساخته می‌شه. متغیرهایی مثل `{INDEX}` و `{PORT}` که به اطلاعات جغرافیایی نیاز ندارن بدون جستجو هم همیشه مقدار می‌گیرن.

!!! note "توجه"
    اسم هر کانفیگ باید یکتا باشه، چون کلاینت‌ها پروکسی‌هاشون رو با هم شناسایی می‌کنن. اگه قالب شما چیزهایی که کانفیگ‌ها رو از هم جدا می‌کنن (پورت، پروتکل، نسخه chain، آدرس) نداشته باشه، پنل خودش موارد جا افتاده رو به آخر اسم اضافه می‌کنه. مثلاً یه قالب ساده `{FLAG}{COUNTRY}` هم اسم‌های متمایزی مثل `🇩🇪Germany VL 443 #1` می‌سازه.

## اطلاعات جغرافیایی مربوط به خروجیه، نه آدرس کانفیگ

متغیرهای جغرافیایی (`{FLAG}`، `{COUNTRY}`، `{CITY}`، `{REGION}`، `{ISP}`، `{ASN}`، `{TYPE}`) آدرس IP‌ای رو توصیف می‌کنن که ترافیک از اون **خارج** می‌شه — همون چیزی که سایت مقصد می‌بینه — نه آدرسی که کلاینت به اون وصل می‌شه. IP‌های لبه Cloudflare عمدتاً به کشور ثبت‌شده خود Cloudflare نسبت داده می‌شن، پس برچسب زدن اون‌ها گمراه‌کننده بود.

در حالت Proxy IP، خروجی اولین Proxy IP‌ای هست که تنظیم کردید؛ در غیر این صورت خروجیِ خود Cloudflare هست که یک‌بار اندازه‌گیری و کش می‌شه. `{EGRESS_IP}` همون آدرس رو چاپ می‌کنه. اگه خروجی قابل تشخیص نباشه، این متغیرها به اطلاعات جغرافیایی آدرس کانفیگ برمی‌گردن.

## اسم دلخواه برای هر IP

اگه بخواید به یه IP مشخص یه اسم ثابت بدید، هر خط از کادر **Clean IPs** یا فقط خود آدرسِ host هست یا به شکل `host # Name` — بخش بعد از اولین `#` اسم اون کانفیگه که به عنوان `{IPNAME}` نمایش داده می‌شه. برای مثال:

```
1.2.3.4 # سرور من
1.1.1.1 # Cloudflare
1.0.0.1
```

هر کانفیگی که آدرسش با یه خط بالا مطابقت داشته باشه، به جای `{IPNAME}` از اون اسم استفاده می‌کنه. آدرس‌ها دقیقاً همونطوری که نوشته شدن مطابقت داده می‌شن (براکت‌های IPv6 حذف می‌شن). یه خط مثل `1.2.3.4 #` که اسمش خالیه فقط همون آدرسِ خالی از اسم رو اضافه می‌کنه. وقتی قالب فعال باشه، URIهای واردشده‌ای که فرمتشان پشتیبانی می‌شود هم با `KIND=Imported` نام‌گذاری می‌شوند؛ فرمت‌های خارجی ناشناخته بدون تغییر باقی می‌مانند.

## تست خودکار تأخیر

`{LATENCY}` با یه **تست خودکار** اختیاری — یه چک‌باکس در بخش اسم کانفیگ‌ها که به‌صورت پیش‌فرض خاموشه — تازه می‌مونه. وقتی فعال بشه، پنل به‌صورت دوره‌ای آدرس‌هایی که کانفیگ‌ها به اون‌ها وصل می‌شن رو با بازه زمانی که انتخاب می‌کنید (۱۰ تا ۱۴۴۰ دقیقه) دوباره اندازه می‌گیره تا `{LATENCY}` نتایج اخیر رو نشون بده. وقتی خاموش باشه، `{LATENCY}` مقدار `--` نشون می‌ده. توجه کنید این کار مقدار کمی درخواست از ورکر مصرف می‌کنه.

تأخیر از سمت شبکه Worker اندازه گرفته می‌شه — یعنی سرعت رسیدن لبه Cloudflare به اون آدرس — نه تأخیر محلی شما. اندازه‌گیری با یه درخواست ساده HTTP انجام می‌شه، پس اون رو یه رتبه‌بندی نسبی بین آدرس‌ها در نظر بگیرید نه عدد دقیق برای اتصال خودتون.

تست دستی صفحه Proxy IP جداست: اون سلامت Proxy IP‌های عمومی همون صفحه رو بررسی می‌کنه و روی `{LATENCY}` تأثیری نداره.

## قالب‌بندی و حریم خصوصی

در بخش نام کانفیگ می‌توانید قالب‌بندی **Readable**، **Compact** یا **ASCII-safe** را انتخاب کنید و حداکثر طول نام را هم تعیین کنید. نویسه‌های کنترلی حذف و فاصله‌های تکراری جمع می‌شوند.

برای جستجوی جغرافیایی سه حالت وجود دارد: **Automatic** که در صورت نیاز داده را از سرویس جغرافیایی می‌گیرد و cache می‌کند، **Cached data only** که فقط از داده‌های موجود استفاده می‌کند و درخواست جدید نمی‌فرستد، و **Disable geo lookups** که جستجوی جغرافیایی را کاملاً خاموش می‌کند. متغیرهای `{GEO_AGE}` و `{LATENCY_AGE}` عمر داده‌های cache را نشان می‌دهند و در بخش اختیاریِ بدون مقدار حذف می‌شوند.
